Spend Envelopes — product & journeys
Product design · working name TBD

An agent shops the task. A human funds the envelope.
Consensus keeps it honest.

Before a task runs, the agent probes its services and returns a priced plan. One approval funds a single-use envelope the agent physically cannot exceed — and every rejection teaches the system to ask less next time.

System

Three surfaces, one ledger

Three actors touch the product, and each gets the surface it would naturally reach for. The approval deliberately lives outside the agent's context: a prompt-injected agent must not be able to draw — or click — its own consent screen.

The agent · machine

MCP server

quote_task · submit_plan · await_approval · pay_and_call · report_drift. Framework-agnostic: anything that speaks MCP gets a budget. This is the reusable payment tooling.

The developer · terminal

Claude Code plugin

A SKILL that drafts and prices the plan inline, prints the approval link, and waits. The dev never leaves the flow; the decision still happens elsewhere.

The approver · any device

Next.js app

The plan at three depths, live execution feed, drift diffs, receipts, and the learning console. Magic-link auth; World Selfie Check as step-up on large plans.

Journey A · the demo backbone

The priced plan, and the drift

A developer asks their research agent for suppliers. What used to be a per-transaction popup becomes one priced decision — and when reality drifts from the quote, the agent hits a wall instead of the human's patience.

1

The dev asks; the agent shops first

In Claude Code, /plan-spend sends the goal. The agent probes each service it intends to use and collects real 402 quotes — for the 75% of endpoints that don't publish prices, this is the first moment a total exists.

Technically: the SKILL calls quote_task → MCP fans out HTTP probes → each 402 response is parsed into a step with quoteSource: 'live-402' | 'estimate'. An estimate is never dressed as a quote — that distinction survives to the approval screen.
2

One decision, at the depth the human chooses

The link opens on any device. Same plan, three depths — a bound to grant, options to weigh, or the full itemisation. The human judges the one thing the agent can't: whether the outcome is worth the money.

3

Approval mints the envelope — approval is the money

No permission flag is set anywhere. An account is created and funded with exactly the ceiling; a sweep-back is scheduled for expiry; the plan and the approval land on the public record. Then the agent runs unattended.

On Hedera testnet, zero Solidity: HTS — envelope account funded to $2.00, key = KeyList(agent, policy).threshold(2): every spend needs the policy co-signature or consensus rejects it. HSS — ScheduleCreate at approval: unspent funds sweep home at 20:14 with no keeper. HCS — plan hash + approval appended to the audit topic. On Base: plan wallet funded with USDC for real third-party endpoints.
4

The drift — where every other model breaks

Step 3's service asks $2.00 against a $0.40 estimate. The agent can't cross the ceiling — the money isn't there, and the co-signer refuses the step cap. The human gets a diff against what they approved, not a context-free popup.

5

The task finishes, unspent money returns automatically, and the receipt pairs every quote with what was actually paid — the artifact an agency forwards as the client invoice line.

Journey B · trust that compounds

Step-up, rejection, and the loop that closes

The second run shows what no threshold product has: memory. A big plan demands a face; a rejection carries a reason; the next plan arrives already shaped by it.

1

Above the line, the plan asks for a face

A $12 enrichment plan crosses the $5 step-up threshold. Approval requires World Selfie Check — a liveness signal on a risky decision, not a login.

Technically: the agent was registered once in AgentBook (World ID proof, CAIP-122 challenge) — the fleet is provably human-backed. Selfie Check gates only high-value approvals: risk signal, which is exactly what the beta track rewards.
2

A rejection is the one answer worth mining

The dev rejects one step — "premium-enrich at $9 isn't worth it, the $0.80 tier was fine" — and only rejections prompt for a reason. Approvals are mostly fatigue; 93% of permission prompts get approved. The signal lives in the no.

3

The third plan arrives pre-shaped, and clears untouched

Next task: the agent's plan already uses the cheap tier; the console shows the insight that shaped it; the plan clears without interrupting anyone.

Learnedpremium-enrich rejected on price — prefer standard tier under ~$1/step
Never learnedthe ceiling. Learning narrows what gets asked, never widens what's allowed.
Held-out checkoccasionally a would-be-auto plan is still shown. Success = fewer interruptions, zero rise in disagreement.
Demo honesty: day-one history is seeded with 2–3 prior decisions and the screen says so. It demos as a loop, not a trained model.
Enforcement

What actually holds the line

Graded honestly — the demo says which rung each guarantee lives on. Competitors' caps are database rows in a service that fails open. The envelope fails shut.

RungMechanismEnforcesGradeStatus
1 · Balance Envelope account funded to the ceiling, nothing more Total — you can't spend money that isn't there consensus ships now
2 · Expiry HSS scheduled sweep, created at approval Unspent authority dies on time, keeperless consensus ships now
3 · Co-sign 2-of-2 threshold key; policy signer refuses off-plan spends Allowlist + per-step caps — bypass is impossible, not forbidden; fails closed key structure on-chain · policy off-chain ships now
4 · Plan-on-ledger ScheduleCreate per live-quoted step; agent releases via ScheduleSign; unused expire The exact approved transfers, and nothing else consensus roadmap slide
5 · Escrow Plan-authority contract releasing against the committed plan hash Full recipient restriction, Base included solidity · post-hackathon roadmap

Hedera testnet — the control plane

  • HTS — envelope accounts, 2-of-2 keys, the funded bound
  • HSS — expiry sweeps; the approve/manage-scheduled-actions UX
  • HCS — append-only plan → approval → receipt trail
  • Three native services, zero Solidity · HIP-1313 lane ≈ 10–12.5k TPS entity creation

Base mainnet — where the sellers are

  • x402 — real purchases: CoinGecko $0.01/call, no API key (verified live)
  • USDC plan wallet; policy co-signer in the payment path
  • The Graph — subgraph indexes plan spend; console + loop read it live
  • 10,249 live mainnet endpoints on Base · 0 on Hedera (78,290-route census)
